Summary
Security audit of the API + fixes for the critical findings. Full report of everything scanned (including issues left as follow-ups) is below.

Fixed in this PR
1. Overly permissive CORS (critical) — main.ts called app.enableCors() with no config, allowing any origin. Now driven by a CORS_ORIGINS env allowlist (comma-separated), defaulting to the app's own BASE_URL:

app.enableCors({
  origin: CORS_ORIGINS?.split(',').map(trim) ?? [BASE_URL],
  credentials: true,
  methods: ['GET','POST','PATCH','DELETE','OPTIONS'],
});
2. Missing security headers — added helmet() middleware in main.ts (app.use(helmet())).

3. No brute-force protection on auth (missing protection) — added @nestjs/throttler with a global ThrottlerGuard (100 req/min default) plus a tight @Throttle(5/min) on POST /auth/login, /auth/recovery, and /auth/reset-password.

4. Internal error/detail leakage — AuthRepository.resetPassword wrapped everything in catch (error) { throw new InternalServerErrorException(Error ${error}) }, leaking raw internals and turning auth failures into 500s. Now rethrows HttpExceptions, maps invalid/expired tokens to 400, logs the rest via Logger, and returns a generic message. Replaced all remaining console.log(error) (auth/user services + user repo) with Logger.error, per the repo's own AGENTS rule.

5. Insecure dependencies — npm audit reported 4 vulns (3 high). Bumped nodemailer to ^9.0.3 (arbitrary file read / SSRF / CRLF injection / TLS bypass advisories) and added overrides to pull patched transitive uuid (^11.1.1) and linkify-it (^5.0.2) through the @nestjs-modules/mailer → preview-email → mailparser chain. npm audit now reports 0 vulnerabilities.

6. Weak password policy (unvalidated input) — added @MinLength(8) to CreateUserDto.password and ResetPassDto.newPassword (previously only @IsString()).

Scan results (no code change needed)
Hardcoded secrets: none found. Only .env.example (empty placeholders) is tracked; .env/.env.docker are gitignored.
SQL injection: none. All DB access goes through Prisma with parameterized args; the one $queryRaw (health check) is a static SELECT 1. BaseRepository.buildFilters feeds user search into Prisma contains, which is safe.
Unvalidated input: global ValidationPipe({ whitelist, forbidNonWhitelisted }) + per-DTO class-validator decorators are solid; only the password policy gap above.
Missing auth checks: JwtAuthGuard is global via APP_GUARD; open routes are explicitly @Public(); role-restricted routes use @Roles() + RolesGuard. Coverage looks correct.
Follow-ups (reported, not changed to keep scope focused)
User enumeration: POST /auth/recovery returns 404 "No existe el usuario con el email X" for unknown emails, revealing which addresses are registered. Recommend a uniform response regardless of existence.
Debug/doc exposure: GET /auth/test echoes the JWT payload, and Swagger /docs is served in every environment. Consider gating both behind non-production config.
JWT_SECRET not validated at boot — if unset, tokens are signed/verified with undefined. Recommend failing fast on startup.
